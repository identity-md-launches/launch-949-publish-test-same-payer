# Implemented design

## Overview

This is a minimal publication test for a reader confirming the displayed phrase and opening existing files. The page has one heading followed by a file list only when files exist. All HTML and CSS live in `src/index.html`; the list is generated by `scripts/build.ts`. The final export is `dist/index.html`.

## Colors

The `:root` tokens in `src/index.html:9` use hex values:

| Token | Value | Role |
| --- | --- | --- |
| `--color-page` | `#ffffff` | Page background |
| `--color-text` | `#111111` | Heading and default text |
| `--color-link` | `#0044aa` | Unvisited file links |
| `--color-visited` | `#663399` | Visited file links |

This is a light-only page. Keyboard focus uses the browser's unmodified indicator, including system handling of forced colors. No custom focus color, status palette or gradients exist. Measured rendered contrast on white was 18.88:1 for the heading and 8.72:1 for the fixture's unvisited links. Visited color was source-reviewed only.

## Typography

Use `system-ui, sans-serif`; no font files or network font dependencies exist. `--text-body` is `1rem` (16px at the tested browser default), with normal weight and a unitless 1.5 line height. `--text-heading` is `1.5rem` (24px), with weight 700, line height 1.4 and balanced wrapping. Letter spacing remains normal. System font appearance can vary by platform.

File links retain their full names, remain selectable, use `overflow-wrap: anywhere`, and place names in `<bdi>` for direction isolation. Underlines use the font's thickness and position metrics. Nothing is truncated.

## Layout

`--space-page: 1.5rem` supplies page padding. `main` uses `max-inline-size: 48rem` and stays at the leading edge. `--space-list: 1rem` separates the conditional list from the heading. The list has `1.5rem` inline-start padding. Links use `0.625rem` block padding and at least 44px block size.

Content flows in a single column with no breakpoints, fixed heights or positioned elements. The viewport meta permits zoom. At 320px the heading wrapped to two lines; at 768px and 1280px it occupied one line. All tested widths had no horizontal overflow. At a 200% root font size and 320px width the three-line heading remained readable without horizontal scrolling; this was text enlargement, not native browser zoom.

## Elevation & Depth

The surface is flat, with no cards, borders, shadows, overlays or stacking layers.

## Shapes

There are no decorative shapes or radii. File links retain the native keyboard focus outline.

## Components

- **Page shell:** `src/index.html:21` and `:54`. A normal-flow `main` contains a single `h1`. No repeated navigation requires a skip link.
- **File list:** `scripts/build.ts:36` and `src/index.html:38`. A native `ul`/`li`/`a` structure appears only when existing regular files are found. Labels are filenames relative to `line-1/`; URLs are relative to the page. Native Tab/Enter and pointer navigation work. Links are underlined and have a visited state. Focus is left to the browser. There are no loading states, forms or animations.
- **Empty state:** the requested heading alone. No extra message or action is invented when files are absent.

## Do's and Don'ts

- Keep the exact requested heading and the conditional file list as the page's only visible content.
- Reuse the source template and its semantic tokens for changes; regenerate the export after editing.
- Preserve existing file bytes, full labels, encoded relative links and native focus behavior.
- Keep text in normal flow and able to wrap. Additional pages, decorative UI and application controls are outside this implementation.
